# 已采集数据说明

本目录是**历史采集的数据**,与 `waypoint/data/`(脚本运行时的输出目录,出厂为空)分开存放,
避免新跑的数据和旧数据混在一起分不清。

CSV 各列的含义见**包根目录 `README.md` 第 4 节**,这里只说明每个文件的**身份与可信度**。

> **范围**:只保留与本包四项功能(DVL 读数 / 可视化 / 定高 / 定高前进)直接相关的数据。
> 原项目中 `go_waypoint`、压力深度 PID/MPC、系统辨识等脚本未收录,其数据也已一并移除。

---

## ⚠️ 读这些数据前必须知道的三件事

2026-09-17 是第一次完整水下测试,过程中**查出并修复了 5 个问题**。因此**采集时间决定了数据可信度**:

| 问题 | 发现时间 | 影响 |
|---|---|---|
| `JS_GAIN` 出厂仅 0.2(上限 0.5) | 约 11:30 | 此前推力严重不足,深度/水平都推不动 |
| `sign_z` 符号反了 | 约 11:50 | 此前垂直方向指令是反的 |
| 深度源被 `VFR_HUD`(恒 0)污染 | 约 16:40 | **所有基于压力深度的数据不可信** |
| **Cockpit 手柄以 25Hz 抢 `MANUAL_CONTROL`** | 约 15:55 | **此前 go_forward 数据普遍受污染**(约 70% 指令被冲掉) |
| DVL 丢帧/跳变被误判 | 约 17:10 | 会造成任务被误中止 |

**→ 唯一完全干净的真机数据是 `go_forward/clean_1m*.csv`(16:01 与 16:17,手柄冲突修复之后)。**

## 2. `sitl/` — 仿真数据(**不是真机**)

用于验证代码逻辑与故障处理,**动力学与真机差异很大,不可用于标定参数**:

- 仿真 surge 在 `u=0.6` 终速约 **1.2 m/s**,真机实测仅 **0.06 m/s**(差约 20 倍)
- 垂直需人为设 `--net-buoy 48` 才能匹配真机的悬停推力

| 子目录 | 内容 |
|---|---|
| `altitude_hold/` | 高度闭环 SITL 验证(含 `guard` = alt_min 保护逻辑) |
| `go_forward/` | `sitl`~`sitl5` 迭代;**故障注入**:`drop`=丢帧容错、`glitch`=高度外点+航向尖刺、`yawshift`=航向参考系平移、`badsign`=vx 符号反向 |

## 4. 建议怎么用这批数据

1. **要真机高度控制基线** → `real_2026-09-17/altitude_hold/altitude_hold_tuned.csv`
2. **要真机定高前进基线** → `real_2026-09-17/go_forward/go_forward_clean_1m.csv`(唯一完全干净的)
3. **要 DVL 原始流/噪声特性** → `real_2026-09-17/dvl_raw/*_105453.csv`
4. **要重新标定推力-速度曲线** → ⚠️ 现有曲线来自受污染的 `f05`,**建议在干净环境重测**
5. 画图可直接用包内 `python waypoint/plot_dvl_traj.py --vel <vel.csv> --pos <pos.csv>`
